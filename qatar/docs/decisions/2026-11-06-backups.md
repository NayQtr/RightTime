# Backups: encrypted dump now, Supabase Pro at launch (item 13a)

**Date:** 6 Nov 2026. **Status:** Claude's recommendation; the owner said do it.

**Context.** The production database is on Supabase's Free plan, which keeps no backups (baseline checklist point 10).

**Decision.** Now: a daily `pg_dump` of the `public` and `app` schemas by GitHub Actions
(`.github/workflows/db-backup.yml`, `qatar/ops/db-backup.sh`), encrypted with age before it leaves the runner, kept 14
days as a workflow artifact. Only the owner's offline private key can open it. At launch: move production to Supabase
Pro, which adds daily backups kept by Supabase.

**Why.** Free (GitHub Actions minutes), safe in a public repository (encrypted), and restorable with standard tools; a
local round trip on 6 Nov gave identical row counts in all 51 tables. Pro costs money, so it waits for launch.

**Open (owner):** make the age key, add the secrets `SUPABASE_DB_URL` and `BACKUP_AGE_RECIPIENT`, run it once, test a
restore on staging. Steps: `qatar/docs/ops/backup-restore.md`.

**Revisit** at launch (Pro, and whether point-in-time recovery is worth its price), or if the dump outgrows the job's
20-minute limit.
